# 011 测试沉淀（脱敏）

- 固定 commit 不足以识别产物：记录真实二进制和依赖、编译时外置兼容文件。无人工框架源码修改与“原镜像直接编译通过”是不同事实。
- 可见设备顺序必须通过 ACL 或等价运行时映射核对实际物理卡，不能从 npu-smi board/chip 序号直接猜。
- xTask 的已有容器/指定产物能力曾需要外部适配。后续版本按能力检查，不重复携带历史补丁，也不能只填两个 JSON 和 YAML 就假定功能存在。
- 请求数显式锁定，检查是否被参数扫描或 runner 默认值乘以并发。
- 图模式、no-padding、double-buffer、prefill 和内存比例显式记录；不同历史测试可能不同，不能拿后来修改的 run.sh 替代原配置。
- 图捕获会积累状态，服务复用顺序和 smoke 也是复现条件。发生 OOM 后保留失败和 retry，不能为了通过而静默改参数。
- 曾出现客户端返回 0、但正式请求 39/40 成功的情况。检查请求数据库及服务退出，而不是只看工具返回码。
- EvalScope 指标名称和单位会变；版本、原始结果及重算规则同时保留。
- SSH 断线和目标机器本地服务异常分别定位。重连后先读证据和进程身份，不重复启动同一端口。
- 特性清单开关值使用 true/false/default；输入输出长度、平均 E2E 与全部指标均纳入交付。

- 原生交付与内部执行分开：YAML 中记录版本不等于 xTask 会解释自定义字段。交付只能使用原生字段，源码/编译走原生工具说明，不把 workflow 私有解析器变成接收方依赖。
